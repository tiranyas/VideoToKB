<task type="auto">
  <name>Task 1: Add onboarding redirect to middleware</name>
  <files>src/middleware.ts</files>
  <action>
    Update `src/middleware.ts` to redirect un-onboarded users to /onboarding:

    1. After the existing `if (!user && !isPublicRoute)` redirect block, add an onboarding check:
       ```typescript
       // Redirect un-onboarded users to /onboarding
       if (user &&
           !request.nextUrl.pathname.startsWith('/onboarding') &&
           !request.nextUrl.pathname.startsWith('/api/') &&
           !request.nextUrl.pathname.startsWith('/auth/') &&
           !isPublicRoute) {
         const onboarded = request.cookies.get('kbpipe-onboarded')?.value;
         if (onboarded !== 'true') {
           const url = request.nextUrl.clone();
           url.pathname = '/onboarding';
           return NextResponse.redirect(url);
         }
       }
       ```

    2. IMPORTANT exclusions to prevent infinite loops and broken API calls:
       - `/onboarding` itself (already excluded above)
       - `/api/` routes (API calls from the wizard itself need to work: /api/scrape-context, /api/scrape-template)
       - `/auth/` routes
       - Public routes (already handled)

    3. This is a COOKIE-ONLY check (per Pitfall 1 in RESEARCH.md) -- no DB query. Zero latency impact.

    4. Existing users who have already onboarded won't have the cookie, so they WILL be redirected on first visit after deploy. The wizard pre-fills their existing data and they can click "Skip setup" immediately, which sets the cookie. This is intentional -- it catches existing users per the locked decision "catches existing users too".

    5. Alternative consideration: If forcing existing users through is too aggressive, add a one-time Supabase check client-side in the wizard that auto-sets the cookie if workspace already has branding colors set and redirects back. But start with the simpler cookie approach first.
  </action>

  </verify>
  <done>Middleware redirects un-onboarded users (no cookie) to /onboarding. API routes and onboarding route itself are excluded. Cookie-only check, no DB latency.</done>
