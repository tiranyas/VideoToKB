<task type="auto">
  <name>Task 2: Auth helper and E2E tests for login + articles</name>
  <files>e2e/helpers/auth.ts, e2e/login.spec.ts, e2e/articles.spec.ts</files>
  <action>
    1. Create `e2e/helpers/auth.ts` with a function to inject Supabase auth cookies for E2E tests. Since Supabase uses `sb-{ref}-auth-token` cookies, the helper should:
       - Accept a `BrowserContext` from Playwright
       - Use Supabase admin API (via env vars `NEXT_PUBLIC_SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`) to create a test user session
       - Extract the project ref from `NEXT_PUBLIC_SUPABASE_URL` (the subdomain, e.g. `abcdefg` from `https://abcdefg.supabase.co`)
       - Call `supabase.auth.admin.generateLink({ type: 'magiclink', email: E2E_TEST_EMAIL })` or `supabase.auth.admin.createUser()` + `supabase.auth.admin.generateLink()` to get a valid session
       - Alternatively, use `supabase.auth.admin.createUser({ email, password, email_confirm: true })` then sign in with `supabase.auth.signInWithPassword()` to get access_token and refresh_token
       - Set the auth cookie on the browser context using `context.addCookies([{ name: 'sb-{ref}-auth-token', value: JSON.stringify({ access_token, refresh_token, ... }), domain: 'localhost', path: '/' }])`
       - Also set `kbpipe-onboarded` cookie to `true` to bypass onboarding redirect (see middleware.ts line 62-73)
       - If admin API approach is too complex, fall back to a simpler approach: create a `storageState.json` file during global setup with valid cookies, and reference it in test config
       - Export `loginAsTestUser(context: BrowserContext): Promise<void>`
       - Add a comment noting this requires `SUPABASE_SERVICE_ROLE_KEY` and optionally `E2E_TEST_EMAIL` / `E2E_TEST_PASSWORD` env vars

    2. Create `e2e/login.spec.ts` with tests (NO auth needed):
       ```typescript
       test('unauthenticated user visiting / is redirected to /landing', async ({ page }) => {
         await page.goto('/');
         await expect(page).toHaveURL(/\/landing/);
       });

       test('login page shows email input', async ({ page }) => {
         await page.goto('/login');
         await expect(page.getByRole('textbox', { name: /email/i })).toBeVisible();
       });

       test('login page shows submit/sign-in button', async ({ page }) => {
         await page.goto('/login');
         // Look for a submit button by role
         await expect(page.getByRole('button', { name: /sign in|log in|send/i })).toBeVisible();
       });
       ```

    3. Create `e2e/articles.spec.ts` that uses the auth helper to verify authenticated article list rendering (satisfies E2E-04):
       ```typescript
       import { loginAsTestUser } from './helpers/auth';

       test.describe('Articles page (authenticated)', () => {
         test.beforeEach(async ({ context }) => {
           await loginAsTestUser(context);
         });

         test('authenticated user can access /articles without redirect', async ({ page }) => {
           await page.goto('/articles');
           // MUST stay on /articles — not redirect to /landing or /login
           await expect(page).toHaveURL(/\/articles/);
         });

         test('articles page renders article list or empty state', async ({ page }) => {
           await page.goto('/articles');
           await expect(page).toHaveURL(/\/articles/);
           // Page should render either article cards or an empty-state message
           const hasArticles = await page.locator('[data-testid="article-card"], article, .article-item').count() > 0;
           const hasEmptyState = await page.getByText(/no articles|get started|create your first/i).isVisible().catch(() => false);
           expect(hasArticles || hasEmptyState).toBe(true);
         });
       });
       ```

    IMPORTANT: The articles.spec.ts MUST import and use `loginAsTestUser` from the auth helper. The test MUST assert that the page URL is `/articles` (not accept `/login` or `/landing` as passing). This is the critical difference from a smoke test — E2E-04 requires verifying the articles page actually renders for authenticated users.
