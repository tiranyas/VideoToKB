    - Returns 429 JSON with Retry-After header when rate limited

    **File 1: `src/lib/__tests__/api-keys.test.ts`**
    Test the three pure functions from api-keys.ts. These do NOT need mocking (no DB calls) — they use Node crypto directly. Import `generateApiKey`, `hashApiKey`, `keyPrefix` and test return value format, consistency, and uniqueness.

    **File 2: `src/app/api/__tests__/process.test.ts`**
    Create the `src/app/api/__tests__/` directory. Mock all dependencies:
    - `vi.mock('@/lib/supabase/server')` — mock `createClient` to return a fake supabase client with controllable `auth.getUser` response
    - `vi.mock('@/lib/rate-limit')` — mock `rateLimit` to return a limiter with controllable `check` response. Default: `{ ok: true }`
    - `vi.mock('@/lib/supabase/queries')` — mock `checkQuota` to return `{ allowed: true }`
    - `vi.mock('@/lib/pipeline')` — mock `runPhaseA` to call the onProgress callback with a done event, then resolve
    - `vi.mock('@/lib/usage-logger')` — mock `flushUsageLogs` to resolve immediately

    For each test, construct a `new Request('http://localhost/api/process', { method: 'POST', body: JSON.stringify({...}) })` and call the imported `POST` function directly. Assert on `response.status` and parsed JSON body.

    For the SSE success test, just verify the response has `content-type: text/event-stream` and status 200. Do NOT try to consume the stream (it would hang) — verifying headers is sufficient.

    Important: The route calls `await createClient()` which normally uses `cookies()` from `next/headers`. Since we mock `@/lib/supabase/server` entirely, `cookies()` is never called — this avoids the "cookies() can only be called in a Server Component" error.
