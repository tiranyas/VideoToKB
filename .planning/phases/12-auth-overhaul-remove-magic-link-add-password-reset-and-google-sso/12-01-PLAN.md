Create the /auth/confirm server route that handles password reset email links, and update middleware to support the reset flow.

Purpose: Password reset emails need a server-side route to verify the token_hash and create a session before redirecting the user to the new-password form on the login page. The middleware must allow access to this new route and must not redirect authenticated users away from /login during the password reset flow.

Output: Working /auth/confirm route with tests, updated middleware with /auth/confirm public access and reset-password exception.
